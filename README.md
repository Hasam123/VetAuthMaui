VetAuthMaui

Кроссплатформенное мобильное приложение для автоматизации работы ветеринарного кабинета.

Приложение разработано на платформе .NET MAUI и позволяет клиентам просматривать услуги клиники, добавлять питомцев и записываться на приём. Администратор может работать с заявками, управлять расписанием, услугами и медицинскими записями.

Проект создан в рамках выпускной квалификационной работы.

---

Основные возможности

Для клиента

- регистрация и авторизация по номеру телефона;
- просмотр информации о ветеринарном кабинете;
- просмотр списка ветеринарных услуг;
- добавление, изменение и просмотр питомцев;
- выбор услуги, даты и свободного времени;
- создание заявки на приём;
- просмотр своих заявок;
- просмотр статуса записи;
- отмена записи;
- просмотр комментария администратора;
- просмотр личного кабинета.

Для администратора

- отдельная авторизация администратора;
- просмотр общей статистики;
- просмотр всех заявок клиентов;
- фильтрация заявок по дате и статусу;
- изменение статуса заявки;
- добавление комментария для клиента;
- удаление заявки;
- создание и редактирование ветеринарных услуг;
- блокировка недоступного времени;
- заполнение медицинской карты;
- сохранение диагноза, результатов обследования и назначенного лечения.

Архитектура приложения

Проект построен по клиент-серверной архитектуре.

Пользователь
    ↓
Приложение .NET MAUI
    ↓ HTTP-запрос
PHP API
    ↓ SQL-запрос
База данных MySQL
    ↓
JSON-ответ
    ↓
Отображение результата в приложении

Мобильное приложение не подключается к базе данных напрямую. Все операции выполняются через PHP API.

Клиентская часть отвечает за:

- отображение интерфейса;
- проверку введённых данных;
- отправку запросов;
- получение JSON-ответов;
- отображение результатов.

Серверная часть отвечает за:

- обработку запросов;
- проверку данных;
- выполнение SQL-запросов;
- работу с базой данных;
- формирование JSON-ответов.

Основные страницы

MainPage

Стартовая страница приложения.

Содержит:

- вход клиента;
- переход к регистрации;
- переход к авторизации администратора;
- переход к информации о клинике.

ClientRegister

Страница регистрации нового клиента.

Выполняет:

- проверку заполнения полей;
- формирование объекта с данными клиента;
- отправку данных на сервер;
- обработку ответа регистрации.

ClientPage

Личный кабинет клиента.

Отображает:

- имя и телефон клиента;
- список питомцев;
- список заявок;
- последние статусы записей;
- комментарии администратора.

PetsPage

Страница управления питомцами клиента.

Позволяет:

- просматривать питомцев;
- добавлять нового питомца;
- изменять данные питомца;
- удалять питомца.

ServicePage

Отображает ветеринарные услуги, загруженные с сервера.

Для каждой услуги могут отображаться:

- название;
- категория;
- описание;
- стоимость;
- статус активности.

RecordPage

Страница записи на приём.

Клиент выбирает:

- питомца;
- вид питомца;
- услугу;
- дату;
- свободное время;
- комментарий.

Приложение получает свободные интервалы времени с сервера и не позволяет выбрать занятое или заблокированное время.

AdminPage

Главная страница администратора.

Отображает статистику по заявкам:

- общее количество;
- новые;
- принятые;
- выполненные;
- отменённые.

RequestPage

Страница работы с заявками.

Администратор может:

- фильтровать заявки;
- изменять их статус;
- оставлять комментарии;
- открывать медицинскую карту;
- удалять записи.

MedicalRecordPage

Страница заполнения медицинской информации.

Содержит:

- жалобы;
- диагноз;
- результаты обследования;
- назначенное лечение;
- выполненные процедуры;
- дополнительные заметки.

AdminTimePage

Позволяет администратору блокировать время, недоступное для записи.

Статусы заявок

В системе используются следующие статусы:

Код| Значение
"new"| новая заявка
"accepted"| заявка принята
"done"| приём выполнен
"cancelled"| заявка отменена

В базе данных хранится короткий код статуса, а пользователю отображается его понятное название.

Настройка адреса API

Адрес серверного API находится в файле:

Core/ApiSettings.cs

Пример:

public static class Api
{
    public const string BaseUrl =
        "http://192.168.0.130/veterenar/api/";
}

Перед запуском необходимо указать IP-адрес компьютера, на котором работает XAMPP.

Телефон и компьютер должны находиться в одной локальной сети.

Адрес API должен заканчиваться символом "/".

Пример полного адреса:

http://192.168.0.130/veterenar/api/

Требования для запуска

Необходимо установить:

- Visual Studio с компонентом ".NET Multi-platform App UI development";
- .NET 10 SDK;
- Android SDK;
- XAMPP;
- MySQL;
- PHP;
- Git.

Для тестирования можно использовать:

- Android-эмулятор;
- физическое Android-устройство.

---

Запуск серверной части

1. Установить XAMPP.
2. Запустить Apache и MySQL.
3. Поместить папку серверного API в каталог:

C:\xampp\htdocs\veterenar\api

4. Импортировать базу данных через phpMyAdmin.
5. Проверить настройки подключения в PHP-файле базы данных.
6. Узнать локальный IP компьютера командой:

ipconfig

7. Указать найденный IP в "Core/ApiSettings.cs".
8. Проверить API через браузер.

Пример:

http://192.168.0.130/veterenar/api/services/list.php

---

Запуск мобильного приложения

1. Клонировать репозиторий:

git clone https://github.com/Hasam123/VetAuthMaui.git

2. Открыть файл решения в Visual Studio.
3. Дождаться восстановления NuGet-пакетов.
4. Проверить адрес API в "Core/ApiSettings.cs".
5. Подключить Android-устройство или запустить эмулятор.
6. Выбрать Android в качестве целевой платформы.
7. Запустить проект.

Работа с JSON

Данные между мобильным приложением и PHP API передаются в формате JSON.

Пример запроса авторизации:

{
  "phone": "077123456",
  "password": "1234"
}

Пример ответа сервера:

{
  "success": true,
  "message": "Вход выполнен",
  "client": {
    "id": 1,
    "name": "Иван",
    "phone": "077123456"
  }
}

В приложении JSON автоматически преобразуется в объекты C# через:

ReadFromJsonAsync<T>()

Для отправки объектов используется:

PostAsJsonAsync()

---

Хранение состояния

Текущий пользователь хранится в статическом классе "State".

В нём сохраняются:

- идентификатор клиента;
- имя клиента;
- телефон;
- административный режим;
- выбранный питомец;
- текущая медицинская запись.

Это позволяет разным страницам приложения получать данные текущего пользователя.

После выхода данные очищаются методом:

State.LogoutClient();

Особенности проекта

- приложение построено без сложной многоуровневой архитектуры;
- основная логика находится в классах страниц;
- используется простая и понятная структура;

- ошибки подключения обрабатываются через "try-catch";
- время ожидания запросов ограничено десятью секундами;

- навигация реализована через "Shell".

Ограничения текущей версии

Текущая версия является учебной и предназначена для демонстрации работы клиент-серверного приложения.

Основные ограничения:

- адрес API задаётся вручную;
- приложение рассчитано преимущественно на работу в локальной сети;
- состояние пользователя хранится только во время работы приложения;
- административные запросы требуют дополнительной серверной защиты для промышленного использования;
- отсутствуют push-уведомления;
- отсутствует онлайн-оплата;
- не реализована синхронизация с внешними медицинскими системами.

Безопасность

Перед публикацией проекта необходимо убедиться, что в репозитории отсутствуют:

- пароли от MySQL;
- настоящие данные клиентов;
- пароли администраторов;
- API-ключи;
- закрытые конфигурационные файлы;
- дампы базы данных с персональными данными.

Пароли пользователей на сервере должны сохраняться в виде хеша.

Для этого в PHP рекомендуется использовать:

password_hash()

Для проверки пароля:

password_verify()
