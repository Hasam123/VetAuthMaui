# Поля ветеринарного журнала

Добавлены семь необязательных полей:

| Таблица | Поля |
|---|---|
| vladelci | address VARCHAR(255) |
| pets | pol VARCHAR(10) |
| zapic_na_priem | perv_priem_id INT, внешний ключ на собственный id |
| medical_records | data_zabol DATE, pred_diag TEXT, klin_prizn TEXT, ishod VARCHAR(100) |

Старые данные и service_history сохраняются. NULL обозначает неизвестные данные.
Структура применена миграцией `migrations/20261030_clinic_journal.sql`.
Повторно выполнять эту миграцию нельзя: внешний ключ уже создан.

Адрес обязателен при регистрации (проверяется в MAUI и PHP) и редактируется в личном кабинете.
Поле имени при регистрации подписано «ФИО». Старые владельцы без адреса сохраняются.
Пол питомца выбирается в карточке питомца и при создании нового питомца во время записи.
Врач заполняет дату заболевания, предварительный и заключительный диагнозы,
клинические признаки и исследования, лечение, процедуры, исход и заметки.

Связь с первичным приёмом выбирается врачом в медкарте. В список попадают
более ранние завершённые первичные приёмы того же питомца, включая других врачей.
Выбор «Первичный приём / новое заболевание» хранится как NULL.
При выборе повторного приёма врач видит текст последнего завершённого посещения
в рамках выбранного первичного обращения. Включаются предыдущие повторные визиты,
но исключаются текущий приём, более поздние посещения и другие заболевания.
Для отображения используется тот же `Appointment.MedText`, что и в кабинете клиента.
Нельзя ссылаться на себя, на другого питомца, будущий/незавершённый приём
или создавать цепочки повторных обращений.
Сохранение карты, связи и завершение приёма выполняются в одной транзакции.
Для сохранения обязательны жалобы / причина обращения, предварительный или
заключительный диагноз, назначенное лечение или выполненные процедуры.
Пробелы не считаются заполненным полем. Правила проверяются MAUI и PHP;
API изменения статуса также не завершает приём с неполной картой.
Прежние запросы без новых медицинских полей не стирают эти поля.

После изменения приложения серверный API нужно обновить одновременно:

```powershell
.\scripts\Deploy-ClinicJournal.ps1
```

Скрипт проверяет подготовленные PHP-файлы и создаёт резервную копию прежнего API.
Запускать при отсутствии активных пользователей. Настройки серверного db.php сохраняются.
Существующие веб-страницы остаются совместимыми с расширенной схемой; новые формы
реализованы в MAUI. Система серверной авторизации не изменялась.

Проверка на отдельной временной базе:

```powershell
C:\xampp\php\php.exe tests\clinic_journal.php
dotnet build -f net10.0-windows10.0.19041.0 --no-restore
```

## Время записи

Общий clinic_time.php задаёт Europe/Chisinau независимо от php.ini. Расписание передаёт server_now и starts_at в Unix-секундах. Приложение отсчитывает время относительно ответа сервера, удаляет прошедшие интервалы и повторно проверяет выбор перед отправкой. PHP проверяет время перед обработкой и перед созданием заявки в транзакции. Изменение применяется тем же Deploy-ClinicJournal.ps1.

Проверки границ времени: C:\xampp\php\php.exe tests\booking_time.php.
