# Объединённая медицинская карта

`medical_records`: `id INT PRIMARY KEY`, `jaloba TEXT`, `diagnoz TEXT`,
`naz_lech TEXT`, `procedure_done TEXT`, `notes TEXT`, `data_created DATETIME`.

`id` совпадает с `zapic_na_priem.id`, является внешним ключом с
`ON DELETE RESTRICT`, без `AUTO_INCREMENT`. Приём с медкартой нельзя удалить.
В JSON сохранено имя `treatment_notes`; оно соответствует колонке `notes`.
Поле `obsled_result` удалено из формы, моделей и API.

Миграция переносит данные в новую таблицу, затем переименовывает старые таблицы
в `result_obsled_legacy` и `lechenie_legacy`. Они остаются архивом; в них больше
не пишут приложение и обновлённая веб-панель. Лечение без приёма остаётся в архиве.
Старый текст результата обследования добавляется к заметкам с подписью.
Старый `data_created` берётся из даты лечения (точность до дня); если дата
неизвестна — `NULL`. Для новых карт дата проставляется автоматически и не меняется
при повторном сохранении. `service_history` и учётные записи врачей не меняются.

## Применение

Не запускайте SQL отдельно от обновления сервера: старый API и `admin.php`
обращаются к прежним таблицам. Закройте приложение и выполняйте применение
при отсутствии активных пользователей сервера.

```powershell
.\scripts\Deploy-MedicalRecords.ps1
```

Скрипт проверяет подготовленный PHP, включает режим обслуживания через
`.htaccess`, сохраняет файлы и дамп базы в игнорируемую Git папку
`.deployment-backups`, обновляет сервер и выполняет миграцию. Нужен Apache
с разрешённым `AllowOverride AuthConfig` (как в стандартном XAMPP); иначе
сначала остановите доступ пользователей к серверу другим способом.
При ошибке режим обслуживания остаётся включённым для восстановления из копии.
Повторное применение миграции намеренно запрещено.

## Проверка

```powershell
C:\xampp\php\php.exe tests\medical_records_cycle.php
dotnet build -f net10.0-windows10.0.19041.0 --no-restore
```

Тест создаёт отдельную случайно названную базу, копирует структуру, данные и
триггеры, проверяет перенос и запускает отдельный PHP-сервер. Он создаёт
клиента, питомца и приёмы, проверяет чтение и сохранение из API и веб-панели,
отмену, повторную запись, откаты при искусственных сбоях и неизменяемую историю.
Временная база и PHP-сервер удаляются в конце. Рабочие данные не меняются.
Результат сохраняется в `tests/medical_records_results.json`.

Экран общей истории посещений и новая система серверной авторизации
в это изменение не входят.

После миграции `20261027_history_remove_ids.sql` история услуг не содержит
`appointment_id` и `service_id`. В ней остаются названия услуги и врача и
остальные снимки данных. Триггер добавляет историю при первом переходе в `done`;
отдельный триггер запрещает возвращать завершённый приём в другой статус.
Повторное сохранение медкарты с неизменным `done` не добавляет историю.

Для переименования полей на работающем сервере: .\scripts\Deploy-FieldNames.ps1.
Миграция меняет comment на client_comment в zapic_na_priem, а created_at / performed_at на data_created в zapic_na_priem, medical_records и service_history.
